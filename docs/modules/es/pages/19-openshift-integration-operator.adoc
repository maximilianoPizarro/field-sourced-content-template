== Qué aporta este operador

https://maximilianopizarro.github.io/openshift-integration-operator/[OpenShift Integration Operator^] es la capa de ciclo de vida y UX de Apache Camel sobre OpenShift. No reemplaza Camel Quarkus. Diseñás flujos de forma visual, los probás en modo efímero y los promovés a GitOps.

El operador está en el https://operatorhub.io/operator/openshift-integration-operator[catálogo community de OperatorHub^] (`community-operators`, paquete `openshift-integration-operator`, canal `candidate-v0`). El CSV actual en OperatorHub es *0.8.2*. Es software community (Apache 2.0), no un producto soportado por Red Hat.

Este lab completo lo instala con la entrada `clusterGroup.subscriptions` de `values-hub.yaml`. OpenShift GitOps reconcilia un Subscription en el namespace `openshift-integration` (`AllNamespaces`). Cuando el CSV queda en `Succeeded`, la consola de OpenShift muestra *Integration Platform*.

Este módulo complementa xref:05-kaoto-camel.adoc[Kaoto en DevSpaces]. DevSpaces edita rutas YAML en un workspace. El plugin de consola edita custom resources `IntegrationFlow` en el cluster.

image::ROOT:oio-reconciliation-loop.svg[Reconciliación del operador: CR IntegrationFlow a Deployment del worker,width=100%]

== Cómo lo instala este lab

El Pattern crea el namespace `openshift-integration` con un OperatorGroup de alcance cluster y este Subscription:

[source,yaml]
----
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: openshift-integration-operator
  namespace: openshift-integration
spec:
  channel: candidate-v0
  name: openshift-integration-operator
  source: community-operators
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
----

Lite (`values-lite.yaml`) deja este Subscription habilitado para que sigas teniendo Kaoto en la consola cuando DevSpaces está apagado.

== Quick Try (efímero)

Quick Try despliega un worker Camel Quarkus precompilado desde `kaotoDesign` sin Git, Tekton ni Argo CD. Configurá `deploymentMode: EPHEMERAL` y un TTL. Al borrar el CR se eliminan los Deployments con ownerReference.

Aplicá este ejemplo en `openshift-integration` (o en cualquier namespace que el operador observe):

[source,yaml]
----
apiVersion: platform.io/v1alpha1
kind: IntegrationFlow
metadata:
  name: ephemeral-camel-demo
  namespace: openshift-integration
spec:
  engine: CAMEL
  integrationType: CAMEL_ROUTE
  deploymentMode: EPHEMERAL
  kaotoDesign: |
    - route:
        id: quick-try
        from:
          uri: "timer:tick"
          parameters:
            period: 10000
        steps:
          - log:
              message: "Ephemeral quick-try flow"
  ephemeral:
    ttlSeconds: 3600
----

[source,bash]
----
oc apply -f ephemeral-camel-demo.yaml
oc get integrationflow ephemeral-camel-demo -n openshift-integration -w
----

El processor CDC en `kafka-cdc` sigue siendo un Deployment Camel Quarkus del chart cdc-pipeline. Usá IntegrationFlow para rutas nuevas que quieras probar en la consola y promocionalas a GitOps cuando la ruta esté lista.

No apuntes un flow de workshop de larga duración a credenciales de producción desde Quick Try. El TTL apaga el worker; extendelo desde la consola si necesitás más tiempo.

== Workers, MCP y telemetría

El operador elige una imagen de worker precompilada según la ruta (o fijás `spec.ephemeral.workerImage`). Hay imágenes por dominio: core, messaging, HTTP, data, cloud y AI.

image::ROOT:oio-worker-autoscaling.svg[HPA v2 escala cada worker de IntegrationFlow de forma independiente,width=100%]

Las rutas Camel pueden exponer herramientas MCP, y los flows pueden consultar modelos. Eso complementa xref:08-mcp-lightspeed.adoc[Lightspeed MCP] y xref:17-ai-playground-kafka-mcp.adoc[AI Playground + Kafka MCP] que ya tiene este lab.

image::ROOT:oio-mcp-bridge.svg[Puente MCP — las herramientas de IA descubren e invocan rutas Camel,width=100%]

Los workers emiten OpenTelemetry. La consola colorea los nodos del canvas desde un stream SSE de telemetría.

image::ROOT:oio-telemetry-pipeline.svg[Collector OpenTelemetry al overlay SSE de la consola,width=100%]

== Verificar en el cluster

[source,bash]
----
oc get csv -n openshift-integration
oc get subscription openshift-integration-operator -n openshift-integration
oc get consoleplugin
oc get crd integrationflows.platform.io
----

Esperá el CSV `openshift-integration-operator.v0.8.2` (o más nuevo en el canal `candidate-v0`) en fase `Succeeded`, y el ConsolePlugin `integration-console-plugin`. Después abrí *Integration Platform* en la consola.
